# Part 7: more Tommy Script commands (branch `p7-scripts`)

Ask Tommy now answers far more student questions through **151 new command families** over data already in the app, plus a **FAQ bank of 1,124 USC answers** exposed to the translator as one command, `faq {id}`.

## Files (all new; no existing file was edited except one line of `template.html`)
- `js/ta/scripts-plus.js`: the 151 families (`TA.ScriptsPlus`).
- `js/ta/faq-data.js`: generated by `python3 scripts/build_faq.py` from `data/kb.json.gz` (curated USC docs with 7 paraphrases each; answers are the page's own text cut to ≤ 90 words at a paragraph/sentence/bullet boundary, marked "Shortened" when cut; 1–2 source URLs each). Personal/sensitive and basic-needs topics, and topics the families answer (hours, bus schedules), are left out.
- `js/ta/faq.js`: keyword index (idf-weighted paraphrase overlap, ~0.2 ms per lookup, built when the page is idle) and the `faq` command.
- `template.html`: `scripts-plus.js`, `faq-data.js`, `faq.js` load right after `course-info.js`, in that order.
- `scripts/build_faq.py`, `scripts/p7-eval/` (test sets, generator, runner).

## How messages reach the new commands
1. **On device** (`TS.compile`): each family has a narrow `match`. Matchers only claim wording Trojan Assist's brain answered badly on the sample; crisis/safety messages never reach them (`TS.handle` sends flagged text to Trojan Assist first, unchanged).
2. **AI translator**: every family appears in `TA.Script.catalog()` with 2–3 example phrasings, so the translator can pick it for casual wording. `faq`'s catalog line lists `id title` pairs.
3. **No-answer fallback**: `faq.js` wraps `TA.Brain.handle`; only when the brain returns *no answer at all* (and the text is not flagged/personal), a looser FAQ match is tried. On-device strict FAQ matching exists but is off (`TA.FAQ.strict = false`): the brain already answers those paraphrases from the same pages, and turning it on changed no result in the sample.

## Wrapped (not edited) older commands
- `hours.check` looked places up in `TH.DATA` (absent), so "is evk open" failed: its run now uses the place resolver; its match yields to `place.hours` / `open.now` / `dining.halls`; it gained a `day` arg.
- `events.find`, `events.recommend`, `grades.show` yield to a family when that family's matcher claims the message ("events today", "free food today", "what events does X have", "does the ai see my grades", "who can see my grades").
- `course.who` answers codes the NLU misreads (e.g. "ACCT 410", where "acct" is read as slang).

## For the integrator
- Load order matters: `scripts-plus.js` after `course-info.js` (and after `script.js`), `faq-data.js` then `faq.js` right after. `bridge.js`/`act-anything.js` still load after them.
- Rebuild the Netlify translator prompt (`node scripts/build-netlify.cjs`): it captures the new catalogue and `COMMANDS` (adds `faq: ["id"]`, `hours.check` now takes `day`).
- `faq-data.js` is generated: edit `scripts/build_faq.py`, not the data file. It adds ~1.4 MB to the build.
- Account answers (`my.*`) read `TA.State.d` / `TH.H()` on the device and say so; simulated things (orders, rides, bookings, reports) and estimates (kitchen waits, crowd levels) are labeled "Simulated" / "Est.".
- If `script.js` changes command names `hours.check`, `events.find`, `events.recommend`, `grades.show` or `course.who`, the wrappers simply skip (they check the command exists).
